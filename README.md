# Golf Ball Detection and Color Classification

โปรเจกต์ตรวจจับลูกกอล์ฟและแยกสี ด้วย Python + OpenCV (ไม่ใช้ AI / YOLO / ไม่ต้อง train model)
แล้วส่งผลเข้าระบบ IoT: MQTT → Node-RED → InfluxDB/Grafana, Telegram, Google Sheets, n8n + AI

## เริ่มต้นเร็ว (Windows) — สำหรับคนที่ clone ไปทำต่อ

ต้องมี: Python 3.12, VS Code (+ Python extension), Docker Desktop (ต้องมี WSL2), Git

```bash
git clone https://github.com/<เจ้าของ>/golf-ball-vision-iot.git
cd golf-ball-vision-iot
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
docker compose up -d
```

1. **แก้ `.env`** — ตั้งรหัส InfluxDB/Grafana เอง (`INFLUX_TOKEN` ยาว ๆ อะไรก็ได้) ส่วน Telegram /
   Google Sheets / Gemini ใส่ของตัวเอง (เว้นว่างได้ ระบบยังรันได้ แค่ส่วนนั้นจะไม่ทำงาน)
   **ห้ามอัป `.env` ขึ้น GitHub** (อยู่ใน `.gitignore` แล้ว)
2. **เปิดโฟลเดอร์ใน VS Code** → Run and Debug (`Ctrl+Shift+D`)
   - ไม่มีกล้อง: เลือก **3. รีเพลย์ภาพตัวอย่าง samples**
   - มีกล้อง: เลือก **4. สแกนหากล้อง** ดูชื่อกล้อง → แก้ `CAMERA_NAME` ใน `config.py` → **1. ตรวจจับ**
3. **เกณฑ์ใน `config.py` ตั้งจากกล้อง RealSense ที่ระยะ/แสงของเจ้าของ** ถ้ากล้องหรือระยะต่าง
   ให้เก็บข้อมูลใหม่ด้วย **7. เก็บข้อมูลปรับเกณฑ์** แล้ว **8. วิเคราะห์ข้อมูลที่เก็บ** (ดูหัวข้อ "ระยะกล้องใหม่")
4. รายละเอียดระบบ IoT ทุกขั้น (Grafana, n8n, Telegram, Sheets, ZeroTier) ดูที่ **[SETUP_IOT.md](SETUP_IOT.md)**

## การติดตั้ง (Ubuntu 24.04)

เลือกทำ **วิธีใดวิธีหนึ่ง**

### วิธีที่ 1: ใช้ venv + pip (แนะนำ — ได้ OpenCV เวอร์ชันใหม่ และไม่กระทบ Python ของระบบ)

```bash
# 1. เข้าโฟลเดอร์โปรเจกต์
cd ~/miniproject_opencv

# 2. ติดตั้งเครื่องมือสร้าง virtual environment
sudo apt update
sudo apt install -y python3-venv python3-pip

# 3. สร้าง virtual environment ชื่อ .venv
python3 -m venv .venv

# 4. เปิดใช้งาน (สังเกตว่าจะมี (.venv) ขึ้นหน้า prompt)
source .venv/bin/activate

# 5. ติดตั้ง OpenCV
pip install -r requirements.txt

# 6. ตรวจสอบว่าติดตั้งสำเร็จ
python3 -c "import cv2; print(cv2.__version__)"
```

> Ubuntu 24.04 ไม่อนุญาตให้ `pip install` ลง Python ของระบบโดยตรง (จะขึ้น error
> `externally-managed-environment`) จึงต้องใช้ venv

ครั้งต่อ ๆ ไปที่จะใช้งาน ให้สั่ง `source .venv/bin/activate` ก่อนรันเสมอ
และสั่ง `deactivate` เมื่อเลิกใช้

## Phase 2: ตรวจจับวัตถุทรงกลม

```bash
python3 ball_detect.py                 # ตรวจจับด้วยค่าใน config.py
python3 ball_detect.py --camera 0      # เลือกกล้อง
python3 ball_detect.py --tune          # เปิดแถบเลื่อนปรับค่าแบบสด ๆ  ← ใช้ตอนจูน

```

ปุ่มลัดระหว่างใช้งาน: `Q`/`ESC` ออก · `S` บันทึกภาพลง `snapshots/` · `D` ดูภาพขาวดำที่ใช้ประมวลผล

### การจัดฉากทดสอบ (มีผลกับความแม่นยำมากกว่าการจูนค่า)

- **วางกล้องไว้ด้านบนส่องลงมา** จะได้ผลดีที่สุด เพราะฉากหลังกลายเป็นพื้นเรียบ ๆ
  วงกลมปลอมจากขอบโต๊ะ เก้าอี้ หรือสายไฟจะหายไปเกือบหมด
- ใช้พื้นหลังสีเรียบและตัดกับลูกบอล (ลูกกอล์ฟขาว → พื้นเข้ม)
- แสงสว่างสม่ำเสมอ ไม่มีเงาแข็ง ๆ ทับลูกบอล
- ระยะกล้างถึงลูกบอลคงที่ จะทำให้รัศมีที่วัดได้คงที่ไปด้วย
  (สำคัญสำหรับ Phase 3 ที่ต้องเทียบขนาด)

### วิธีจูนค่าให้เจอลูกบอล

รัน `--tune` แล้วเอาลูกบอลมาวางหน้ากล้อง ปรับทีละตัวตามตารางนี้:

| ค่า | ความหมาย | ปรับเมื่อ |
|---|---|---|
| `blur` | ความแรงของการเบลอลด noise | เจอวงกลมปลอมเยอะ → เพิ่ม |
| `minDist` | ระยะห่างขั้นต่ำระหว่างจุดศูนย์กลาง 2 วง | เจอวงซ้อนกันบนลูกเดียว → เพิ่ม |
| `param1` | ความไวของการหาขอบ (Canny) | ขอบลูกบอลจาง ๆ ไม่ถูกจับ → ลด |
| `param2` | คะแนนขั้นต่ำที่ยอมรับว่าเป็นวงกลม | **ตัวสำคัญที่สุด** — เจอยาก → ลด, เจอของปลอมเยอะ → เพิ่ม |
| `minRadius` / `maxRadius` | ช่วงขนาดที่สนใจ (พิกเซล) | ตัดวัตถุที่เล็ก/ใหญ่เกินไปทิ้ง |

พอได้ค่าที่ถูกใจแล้ว ให้ก๊อปตัวเลขไปใส่ใน `config.py` เพื่อให้เป็นค่าเริ่มต้นครั้งต่อไป

> เคล็ดลับ: **แสงสำคัญมาก** ถ้าห้องมืด กล้องจะเปิดรับแสงนานขึ้นทำให้ FPS ตก
> ภาพมี noise มากขึ้น และขอบลูกบอลจะเบลอจนตรวจจับยาก

เปิดใช้งานเป็นค่าเริ่มต้น ปิดด้วย `python3 ball_detect.py --no-capture`

เมื่อตรวจเจอ โปรแกรมจะแจ้งที่ terminal และบันทึกภาพให้อัตโนมัติ:


**ชื่อไฟล์บอกผลในตัว** เช่น `20260926_063012_golf2_pink-white.jpg`
= เจอลูกกอล์ฟ 2 ลูก สีชมพูกับขาว

**ไฟล์ที่ได้:**
- `snapshots/` - ภาพที่มีกรอบและป้ายกำกับ ใช้เป็นหลักฐานว่าโปรแกรมเห็นอะไร
- `snapshots/clean/` - ภาพต้นฉบับไม่มีอะไรวาดทับ **ต้องใช้อันนี้เวลาวัดค่าย้อนหลัง**
  (จุดแดงที่วาดตรงกลางลูกบอลทำให้ค่าพื้นผิวที่วัดได้เพี้ยนไปถึง +55)
- `detections.csv` - บันทึกทุกครั้งที่เจอ: เวลา ผลตัดสิน สี รัศมี คะแนนพื้นผิว คะแนนขอบ

**กติกาที่กันภาพซ้ำ** (กล้องส่ง ~15 เฟรม/วินาที ถ้าบันทึกทุกเฟรมจะได้ภาพซ้ำ 15 รูป/วินาที):
1. ต้องเจอฉากเดิมติดกัน 5 เฟรม ถึงจะยอมบันทึก - กันภาพที่กะพริบไปมา
2. ฉากเดิมซ้ำต้องเว้น 3 วินาที
3. แต่ถ้า**ฉากเปลี่ยน** (จำนวนลูกหรือสีเปลี่ยน) จะบันทึกทันทีไม่ต้องรอ

ปรับได้ที่ `CAPTURE_STABLE_FRAMES` และ `CAPTURE_COOLDOWN` ใน `config.py`

## Phase 6: หลายลูกพร้อมกัน + สรุปผลตอนจบ

### รองรับหลายลูกพร้อมกัน

ระบบตรวจจับและแยกประเภทลูกบอลทุกลูกในภาพพร้อมกันได้ แถบบนจอจะแจกแจงสีให้ด้วย:

```
Golf Ball: 3 [Neon:1 Pink:1 White:1]   Rejected: 1
```

ป้ายกำกับจะมีเลขลำดับตรงกับวงกลม (`#1`, `#2`, `#3`) และถ้าป้ายจะทับกัน
ระบบจะเลื่อนลงอัตโนมัติจนอ่านออกทุกป้าย จำเป็นเมื่อลูกบอลวางชิดกัน

**บั๊กที่แก้ไปใน Phase นี้:** `HOUGH_MIN_DIST` เดิมตั้งไว้ 60 พิกเซล
แต่ลูกกอล์ฟรัศมี ~27 px เมื่อวางชิดกัน จุดศูนย์กลางห่างกันแค่ 54 px
ซึ่งน้อยกว่า 60 ทำให้ HoughCircles **มองข้ามลูกที่วางชิดกันไป**

| ระยะห่างขอบต่อขอบ | minDist=60 (เดิม) | minDist=45 (ใหม่) |
|---|---|---|
| 0 px (ชิดกัน) | 2/3 ลูก | **3/3 ลูก** |
| 5 px | 2/3 ลูก | **3/3 ลูก** |
| 10 px ขึ้นไป | 3/3 ลูก | 3/3 ลูก |

ทดสอบแล้วว่าการลดค่านี้ไม่ทำให้เกิดวงซ้อนบนลูกเดียว

## โหมดเก็บข้อมูลเพื่อปรับเกณฑ์ (--collect)

ใช้ตอนที่ต้องการหาเกณฑ์ใหม่จากของจริง จะจดค่าทุกเฟรมลง `calibration_data.csv`
โดยไม่บันทึกภาพ (เป้าหมายคือได้ตัวเลขเยอะ ๆ ไม่ใช่ได้ภาพสวย)

```bash
python3 ball_detect.py --camera 2 --collect golf_white
```

ชื่อที่ใส่หลัง `--collect` จะถูกบันทึกในคอลัมน์ "ของจริง" ทำให้รู้ภายหลังว่า
แถวนั้นคือลูกอะไร แม้โปรแกรมจะตัดสินผิดก็ตาม — นี่คือหัวใจของการหาเกณฑ์ใหม่

**ข้อควรระวัง:** โหมดนี้จดทุกวงกลมที่เจอ รวมถึงวงกลมปลอมจากพื้นหลังด้วย
ฉะนั้นควรจัดฉากให้สะอาด มีแค่ลูกบอลลูกเดียวในภาพ

## ข้อจำกัดที่รู้อยู่ (สำคัญ)

**0. มือบังลูกเกินครึ่ง = ถูกนับเป็นสิ่งแปลกปลอม** สีที่วัดได้กลายเป็นสีผิว (H 16-26, S 31-40)
จึงขึ้นว่า `wrong color: Unknown` ในภาพทดสอบเกิด 5 จาก 14 ครั้งที่มือบังลูกนีออน/ชมพู
→ **แก้แล้วด้วย "ภาพต้องนิ่งก่อนถึงจะนับ"** (`utils/motion.py`, `STILL_SECONDS` ใน `config.py`)
ระหว่างที่มีอะไรขยับในภาพ จะไม่บันทึก ไม่ส่งแจ้งเตือน ไม่นับลงกราฟ (บนจอขึ้นตัวแดง *Moving - not counting*)
ลองหามือด้วยสีผิวแล้วไม่ได้ผล: กล้องถ่ายผิวซีดจนสีเดียวกับโต๊ะไม้ (แยกได้ดีสุด 72%)
และการเทียบกับภาพโต๊ะเปล่าได้ 82% (เงาลูกบอลถูกนับเป็นของแปลก) จึงใช้การเคลื่อนไหวแทน
ข้อจำกัดที่เหลือ: มือที่วางนิ่งสนิทค้างไว้ในภาพจะไม่ถูกจับได้

**1. ลูกปิงปองถูกปฏิเสธเพราะ "เป็นสีส้ม" ไม่ใช่เพราะ "เป็นลูกปิงปอง"**
ถ้าเอา**ลูกปิงปองสีขาว**มาวาง ระบบจะมองว่าเป็นลูกกอล์ฟสีขาว เพราะขนาดเท่ากัน
(24-30 px เทียบกับ 25-29 px) และพื้นผิวก็พิสูจน์แล้วว่าแยกไม่ได้ที่ระยะกล้องนี้
ทางแก้ที่เป็นไปได้: ขยับกล้องเข้าใกล้จนเห็นหลุมบนลูกกอล์ฟ แล้วเก็บข้อมูลใหม่
→ **ระยะใหม่ (28 ต.ค.) เห็นหลุมแล้ว** ลูกกอล์ฟขาวได้คะแนนพื้นผิว ~47 ปิงปองส้มได้ ~5
แต่ยังไม่มีข้อมูลลูกปิงปองสีขาวจริง ถ้ามีลูกให้เก็บด้วยชื่อ `pingpong_white` แล้วอาจเปิด
เกณฑ์พื้นผิวเฉพาะลูกสีขาวได้ (ใช้กับทุกสีไม่ได้ เพราะลูกนีออนสว่างจนหลุมหาย)

ด้วย `--collect` แล้วปรับ `GOLF_RADIUS_RANGE`

**3. เกณฑ์สีผูกกับสภาพแสง** ค่า H ของลูกขาว (117-169) เป็นผลจากสมดุลแสงขาว

## Phase 4: แยกสีลูกกอล์ฟ

ทำงานอัตโนมัติอยู่ใน `ball_detect.py` แล้ว ชื่อสีจะขึ้นใต้ลูกบอลที่ตรวจเจอ
รองรับ 3 สี: **White / Neon / Pink** ถ้าไม่เข้าเกณฑ์สีไหนเลยจะขึ้นว่า `Unknown`

ใช้ระบบสี **HSV** ไม่ใช่ RGB เพราะ HSV แยก "เนื้อสี" (Hue) ออกจาก "ความสว่าง" (Value)
ทำให้ทนต่อแสงที่เปลี่ยนไปได้ดีกว่ามาก และวัดเฉพาะเนื้อใน 70% ของลูกบอล
เพื่อไม่ให้สีพื้นหลังที่ขอบเข้ามาปน

### ค่า HSV จริงที่วัดได้จากลูกกอล์ฟทั้ง 3 สี

วัดจากกล้อง Rapoo วางส่องลงมาจากด้านบน แสงในห้องปกติ:

| ลูก | H | S | V | ผลแยกสี | ระยะห่างจากเส้นแบ่งที่ใกล้ที่สุด |
|---|---|---|---|---|---|
| ชมพู | 173 | 129 | 255 | Pink 100% | ปลอดภัย (S สูงกว่าเกณฑ์ 45 อยู่มาก) |
| นีออน | 30 | 128 | 250 | Neon 97% | **H ห่างขอบล่างแค่ 5** → ขยายขอบล่างเป็น 18 แล้ว |
| ขาว | 33 | 19 | 247 | White 100% | ปลอดภัย (S=19 ต่ำกว่าเพดาน 55 มาก) |

สังเกตว่าลูกขาวกับลูกนีออนมี Hue ใกล้กันมาก (33 กับ 30) แยกกันได้ด้วย **ความอิ่มตัวของสี (S)**
เท่านั้น คือ 19 กับ 128 ซึ่งต่างกันเกือบ 7 เท่า จึงแยกได้ชัดเจน

### ถ้าแยกสีผิด ให้ทำแบบนี้

1. เอาลูกบอลสีที่มีปัญหาวางหน้ากล้อง ให้โปรแกรมจับเจอ
2. **กด `C`** จะพิมพ์ค่า HSV จริงของลูกนั้นออกมาที่ terminal พร้อมคะแนนของทุกสี
3. เอาค่าที่ได้ไปปรับ `COLOR_RANGES` ใน `config.py`

ตัวอย่างค่าที่วัดได้จริงจากลูกกอล์ฟขาวในห้องที่แสงไม่จัด: `HSV = (35, 36, 209)`
→ S = 36 ต่ำกว่าเพดานของสีขาว (55) จึงแยกเป็น White ได้ถูกต้อง

> ระวัง: ถ้าแสงในห้องเหลืองจัด ค่า S ของลูกสีขาวจะสูงขึ้นเรื่อย ๆ
> พอเกิน 55 จะกลายเป็น Neon ทันที (เพราะ Hue ของทั้งคู่อยู่โซนเดียวกัน)
> ถ้าเจออาการนี้ให้ขยายเพดาน S ของ White ขึ้น หรือเพิ่มพื้น S ของ Neon
